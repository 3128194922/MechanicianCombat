### 不能照搬的地方

以下是对所读代码的静态判断，不是已复现的运行故障：

1. **范围边界不一致。** `windBurst` 使用 `center ± radius` 查询实体，但距离衰减使用 `2 × radius`。例如 radius=1.2 时，某些在 2.4 格内的实体可能因不在查询盒内而被漏选。新实现应统一查询边界与球形距离判定，并测试边界。
2. **自定义 tick 绕过了父类完整更新。** 代码为了避开 1.20.1 的空轨迹粒子问题自行移动，需重新核对弹体所有者、射出状态、Forge 碰撞事件、实体移除后的处理与加载边界，不能整段照抄。
3. **缺少完整原版行为证据。** 所读风弹核心类没有实现落地伤害保护记录，`hurt` 固定返回 false；不能据此宣称已经还原反弹、落伤保护或全部方块交互。
4. **渲染采用简化贴图。** 可以参考结构，但视觉是否达到本项目目标要另行对照，不能把其简化外观当作原版一致的证明。
5. **整个参考工程有其他依赖。** [build.gradle](https://github.com/breakinblocks/justtrialspawners/blob/68d4314cfbbf55aa804d898fc944601d2224c87d/build.gradle) 声明 FTB Library 与 Architectury。已读风弹核心主要依赖 Minecraft API 与该项目的配置/注册类，本项目应自行接入配置与注册，不能把整个工程依赖一起搬进来。

## 5. 本项目落地设计

### 5.1 组件分工

以下均为拟定文件，不代表已经创建：

| 组件 | 职责 |
| --- | --- |
| `item/WindChargeItem.java` | 自有风弹物品；手持使用路径与背包发射路径分开处理冷却和消耗 |
| `entity/WindChargeEntity.java` | 所有者、运动、碰撞、直接命中、一次性风爆和实体清理 |
| `combat/WindBurst.java` | 服务端计算范围、距离衰减、遮挡与击退，避免混入菜单或渲染逻辑 |
| `client/entity/WindChargeRenderer.java` | 仅客户端加载的弹体外观 |
| 注册及资源 | 物品、实体、声音、必要粒子、语言文本及模型；统一 `tkgun` 命名空间 |

无需为风弹另加第三方运行依赖。若借鉴主要参考项目的实质代码，应记录固定提交、具体文件及改动，并保留 MIT 版权/许可证；资源来源应单独核实，不将仓库代码许可自动当作所有美术素材的授权证明。

### 5.2 与原背包连接

保留源项目已经确定的背包规则：

1. `BackpackLauncherRules.isLaunchable` 接受本项目的风弹物品，替换不存在的 `Items.WIND_CHARGE` 判断。
2. 服务端发射工厂创建本项目风弹实体；所有者设为发射玩家，出膛位置仍使用原有验证及回退机制。
3. 朝锁定目标或准星方向发射，背包初速度沿用源代码的 **1.6 格/tick**。
4. 成功生成后消耗 **1 个副手风弹与 1 次背包充能**；生成失败不扣除。
5. 保留目标失效、冷却与反馈消息逻辑；不为了手持投掷而让背包额外套用两套冷却或重复扣弹。

### 5.3 行为基准与获取方式

- 推荐以 Java 1.21.1 的玩家风弹行为为对照，使用 1.20.1 原生 API 实现；参考项目提供实现线索，不能取代原版行为核实。
- 击退、直接命中伤害、格挡/反弹、方块交互、击退抗性和落伤保护应分别测试，不以“播放粒子并设置速度”代替完整行为。
- 不扩展加入旋风人、试炼密室、重锤等内容；用户本次决定只涉及风弹。
- **获取方式已确认**：由整合包配置配方或掉落，本模组不内置配方，不添加旋风棒或替代材料配方。对整合包提供稳定的 `tkgun:wind_charge` 物品 ID；具体材料、产量和掉落概率由整合包决定。
- 手持投掷的数值建议先按原版目标核实；参考实现中的 1.5 速度和 10 tick 冷却只是观察值，不是用户已批准的自定义平衡修改。

## 6. 后续验收重点

| 场景 | 需要验证 |
| --- | --- |
| 背包发射 | 方向、出膛点、所有者正确；只扣一次弹药和充能 |
| 碰撞 | 方块/实体命中只爆发一次；不穿过应阻挡的碰撞面；不因贴近发射者立即误撞 |
| 击退范围 | 轴向、斜向、边界和范围外目标一致；遮挡后正确衰减 |
| 多人同步 | 被击退玩家与旁观者看到一致结果；服务端权威处理 |
| 自身助推 | 对地面使用能产生正确推力；落伤规则不是简单永久清零 |
| 异常输入 | 非有限坐标、零向量、非法距离、生成失败无错误扣弹或崩溃 |
| 生命周期 | 只在服务端结算一次伤害/风爆；失效、离开加载范围和清理路径合理 |
| 侧别/兼容 | 专服不加载 Renderer；不要求安装任何参考模组或其额外前置 |

## 7. 恢复实施进度（2026-10-25）

本节记录本次获准恢复实施后的代码状态；前文“方案/拟定/未编写”是报告形成时的历史状态。

- `WindChargeEntity` 保留自有弹体，服务端命中一次后处理风爆；对实体按距离与遮挡衰减击退，并给弹体叠加服务端击退速度。
